# Cellka — Роадмап (после MVP)

План развития по волнам. Каждая волна завершается релизом-тегом.
Правила: задача = issue; задача закрывается только с тестом или замером; релизы — тегами `v*` через существующий `release.yml`.

## Волна 1 → v0.2: Порядок и кластеризация v2

Цель: карта не тормозит на городе-миллионнике, документы соответствуют коду.

- [x] Синхронизировать доки с кодом (MVP_PLAN: кластеризация отмечена; ARCHITECTURE: flutter_map)
- [ ] Адаптивный `maxClusterRadius` по зуму: 60–80 на z≤11, 45 на z=12, 30 на z=13
- [ ] `disableClusteringAtZoom: 13` — на высоких зумах вышки по одной
- [ ] Цвет пузыря кластера по доминирующему оператору (`colorForMnc` большинства маркеров)
- [ ] Spiderfy для совпадающих координат (несколько сот одной БС в одной точке — сейчас до них не дотапаться)
- [ ] Профилирование: вьюпорт с 5–10 тыс. вышек, Timeline-замер; при просадках — `BuilderMarker`; запасной вариант — pre-clustered MBTiles из CI-зеркала
- [ ] Тег `v0.2.0`

## Волна 2 → v0.3: Уникальные фичи

Цель: то, чего нет ни у одного конкурента в РФ-сегменте одновременно.

- [ ] Dual-SIM: `SubscriptionManager`, per-slot списки сот, чипы-фильтры SIM1/SIM2 на карте и в signal strip
- [ ] Круг точности оценки вышки: погрешность из `CellEstimator` → `CircleMarker` («честные данные» против «вышек на воде» у конкурентов)
- [ ] 5G в UI: различение NSA/SA и NRArfcn в Cell Details (маппинг `CellInfoNr` уже есть — задача по UI)
- [ ] Офлайн-кэш тайлов: `flutter_map_tile_caching` для полевой работы без сети
- [ ] Band/частоты вышек, агрегированные из собственных замеров соты

## Волна 3 → v0.4: Замкнутый цикл данных

Цель: краудсорсинг работает как маховик; замеры → база → точность.

- [ ] Встроенный спидтест (download/upload/ping), точки результата привязываются к треку и попадают в GeoJSON-экспорт
- [ ] CA-агрегации (carrier aggregation) в Cell Details
- [ ] Импорт треков GeoJSON/CSV (сейчас только экспорт)
- [ ] Постоянное уведомление / виджет уровня сигнала
- [ ] Пакетная выгрузка в OpenCelliD: ретраи + отчёт «сколько сот принято базой»
- [ ] Внутриприложительная аналитика событий (GA4/Firebase) — после починки подключения GA (коннектор требует переподключения)

## Заметки

- Отзывы сторов не живут в Google Analytics: GA нужен только для событий внутри приложения; отзывы берём из консолей RuStore/Play
- Ориентиры-боли пользователей конкурентов: фейковые/устаревшие позиции вышек, paywall и реклама, потеря записи треков, расход батареи, отсутствие разделения по SIM, ненадёжный спидтест
